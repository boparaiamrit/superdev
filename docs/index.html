From a brief to a released app on Navree.

Superdev is a plugin of 15 skills and 41 agents for Claude Code and Codex. It is the process for taking a product from a PRD and a design to a released, verified app on Navree, the Rust application framework: the order of work, the files written to disk, the rules, and the proof each step needs.

How the work is divided

Navree knows the framework.
Superdev knows the process.

Every Navree app installs Navree's own skills with navree skills:install. Superdev never restates the framework: for every fact it names the Navree skill and the command, and keeps what a framework can't.

What a build does

Ten steps. Each ends with a proof.

The superdev-build skill runs them in order. A plan is confirmed and each module's contract is agreed before its code is written.

Navree and the app

The Navree CLI, the app from the agreed navree new line, Navree's skills, STACK.md.

Digests

The PRD and design extracted into PRD_DIGEST.md and DESIGN_DIGEST.md, without decisions.

Plan

Gaps decided by the operator in GAPS.md; EXECUTION_PLAN.md confirmed before any code.

Foundation

Services, migrations, the security foundation, the demo seed and the first suite. The release binary boots.

Contracts

A contract per module in contracts/, agreed by the operator before its code.

Modules

One at a time: contract, backend, runtime proof, screens, browser proof, suites, a commit.

Audits

The security review, then the product audit: real data, wired controls, readiness.

QA gate

Every route, role, width and colour mode on fresh data, with evidence in every cell.

Deployment

When the operator asks, with Navree's tools and the deploy checklist.

Done

verify-done.mjs --suites --strict exits 0 on the final commit; lessons recorded.

Skills

15 skills that run on their own, too.

The build dispatches them in order, and each one also runs by itself when a request matches it.

superdev-build

Building a product from a PRD and a design as a Navree app, or resuming such a build.

 backend-on-navree

Models, routes, validation, access, workspace scope, lists, jobs, mail, audit, seed data.

 security-foundation

Sign-in, staff, roles, personal data, money or live updates: what Navree gives and what the app builds.

 design-to-navree-ui

A design becomes Navree UI screens, built only from Navree UI components.

 design-to-nextjs

A design becomes a Next.js front end on the Navree API, from its OpenAPI document and types.

 frontend-structure

Laying out, auditing or splitting a module of a Next.js front end.

 prototype-to-navree

A prototype or older product becomes a Navree app without losing what users see.

 design-preservation

A prototype is kept as built and every screen is checked against it.

 design-to-tauri

A desktop or phone client in Tauri on the product's Navree API.

 security-review-and-fix

Before launch or after a large change: a review, a secret scan, a dependency audit.

 product-audit

Is it really done? Real data, wired controls, readiness scores, a full inventory.

 product-qa

Every page and role, contrast, dead links, the phone app; or exploring the running app.

 systematic-debugging

Anything fails: a test, a build, a runtime error, a flaky test.

 superdev-done

Someone asks whether the build is done, and before any claim that it is.

 superdev-self-learning

The operator corrects the approach, a verifier rejects work, or someone says remember this.

Hard rules

25 rules, each with its check.

No rule is a slogan: every one says where it applies and how it is proved. Read them in hard-rules.md.

Before code

  1. 01Install the Navree CLI, create the app and install Navree's skills first
  2. 02Confirm the plan on disk before code
  3. 03Agree each module's contract before its code; one owner

Every module

  1. 04Boot the release binary after each backend module
  2. 05A declaration is not proof

Navree traps

  1. 06Declare access on every route
  2. 07Write inside the request's unit of work; make jobs safe to run twice
  3. 08Validation errors are 400; only Navree UI forms answer 422
  4. 09Keep secrets in .env or the environment
  5. 10Models are global until marked for a workspace
  6. 11SQLite and MySQL have no row-level security

Navree traps

  1. 12Register the audit module; the minimal app does not
  2. 13Give navree check its configuration and a migrated database
  3. 14Fill a gap in Navree UI the Navree way, never with raw markup
  4. 15Fix the cause; add no suppression
  5. 16Never edit a shipped migration; set the production defaults
  6. 17Never edit regenerated files by hand

Product, security, clients

  1. 18Prove every screen in a real browser
  2. 19Give operators structured controls
  3. 20Use one canonical public origin
  4. 21End access the way each client signs in
  5. 22Serialize balance changes per account
  6. 23Make money-moving requests idempotent
  7. 24Publish live updates only after the commit
  8. 25Prove native clients on a device

The done check

Done means verify-done.mjs exits 0.

Not "looks finished". The script runs Navree's checks on the final commit, the Next.js checks only when STACK.md names that front end, and its own checks for the rules a linter can't see.

navree --version matches STACK.md
Navree's skills are installed
cargo fmt, cargo clippy, cargo test
navree check and navree config:check
The release build boots and its health routes answer
No raw markup in Navree UI screens
Every gap row is recorded in the plan
Every public route is declared
No lint suppression added since base_commit

Install

Per project. Never at user scope.

For an existing Navree app, install it in the app. For a new product, install it in the Git folder that holds the PRD and the design; the build creates the app inside it.

Claude Code
$ claude plugin marketplace add boparaiamrit/superdev \
    --scope project
$ claude plugin install superdev@superdev --scope project

# or the helper, which runs both and checks the result
$ bash /path/to/superdev/install-superdev.sh

# NestJS or Laravel project? pin 2.1.0
$ claude plugin marketplace add boparaiamrit/superdev#v2.1.0 \
    --scope project

Requirements

  • The Navree CLI: cargo install navree-cli, Rust 1.95+, a C compiler, and Docker or Podman for a local PostgreSQL/TimescaleDB (SQLite needs nothing)
  • Node.js 22+, only for a Next.js front end and the QA agents' browser tools
  • Claude Code or Codex

Codex

Codex installs Superdev from the repository marketplace .agents/plugins/marketplace.json. See INSTALL.md and CODEX.md.

Built for Navree

navree

The complete application framework for Rust.

Navree gives every application one clear structure: modules wired by dependency injection and checked when the app boots. Auth, workspaces, an ORM, queues, search, real time and AI are in the box. Screens are written in Rust with Navree UI, or in Next.js or Nuxt, and first-party tools handle monitoring, admin and debugging.

Navree is free and open source, licensed MIT OR Apache-2.0, and every app it creates comes with skills for AI coding agents. Superdev is the product process that sits on top of it.
